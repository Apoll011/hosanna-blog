# Why we started building Hosanna

Hosanna did not start as a startup pitch. It started because I was tired of worship software that felt either locked down, stuck in the 2000s, or both.

There are already good tools. Songbook Pro, OpenSong, Planning Center, and a pile of lyric projectors have carried a lot of Sundays. We used some of them. They proved a digital songbook is useful. They also left gaps we kept bumping into: proprietary formats, weak offline behavior, and products that treat the church like a content subscription instead of a team with folders, roles, and flaky venue Wi‑Fi.

So the first version was small on purpose. A ChordPro renderer. Transposition. Charts that still looked like songs when you opened them in a text editor.

## Songs as text, on purpose

ChordPro was not a branding choice. It was the escape hatch.

If your library only lives inside one vendor's database, you do not really own it. Export is a maybe. Migrating churches is a project. Diffing last week's key change against this week's is awkward.

Plain text is boring in the best way. You can edit it, version it, email it, and still read it ten years from now. Early Hosanna leaned hard into that: build a formatting engine around ChordPro, keep the file understandable outside the app, and treat "your songs belong to you" as a constraint, not a slogan.

For a while that *was* the product — a codebase, a growing list of "this would help on Sunday," and no polished marketing site pretending otherwise.

## Then the songbook stopped being enough

A church does not only need a list of charts. It needs the same list on every phone in the band. It needs a service order for Sunday. It needs someone to fix a wrong chord on Friday without breaking Saturday rehearsal. It needs the set to open when the guest network dies during the livestream.

Those problems pulled the project outward. Mobile and Studio started sharing packages. Local storage stopped being an afterthought. Sync became "catch the team up," not "hope the API answers before the intro." Roles and folders showed up because real teams are messy: multi-org musicians, shared libraries, people who should edit charts and people who should only read them.

Hosanna stopped being a ChordPro experiment and became the thing we actually use to prepare worship — still open-source where it counts, still biased toward continuity over cloud theater.

## What has not changed

Plenty of the early UI is gone. The principle is not:

**Help the church prepare. Stay out of the way when the music starts.**

If you want the practical side of that — offline sync, ChordPro editing, service planning — the rest of this blog is the how. This post is just why we bothered in the first place.
